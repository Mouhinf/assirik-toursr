# Plan : Migration Backend de Appwrite vers Firebase

## Objectif
Remplacer Appwrite par Firebase (Firestore) comme backend pour stocker les soumissions de formulaires. L'architecture reste entièrement frontale (client-side).

## Architecture actuelle vs future

### Actuel (Appwrite)
```
Formulaire → Appwrite API → collections (Voyages, Immobilier, Nettoiement, Contacts)
```

### Future (Firebase)
```
Formulaire → Firebase Firestore → collections (demandesVoyages, demandesImmobilier, demandesNettoiement, contacts)
```

## Clés Firebase nécessaires

Pour configurer Firebase côté frontend, tu dois fournir **6 valeurs** depuis la console Firebase :

### Depuis : Firebase Console → Paramètres du projet → Vos applications → Application Web

1. **`VITE_FIREBASE_API_KEY`** → champ `apiKey`
2. **`VITE_FIREBASE_AUTH_DOMAIN`** → champ `authDomain` (ex: `assirik-toursr.firebaseapp.com`)
3. **`VITE_FIREBASE_PROJECT_ID`** → champ `projectId` (ex: `assirik-toursr`)
4. **`VITE_FIREBASE_STORAGE_BUCKET`** → champ `storageBucket` (ex: `assirik-toursr.firebasestorage.app`)
5. **`VITE_FIREBASE_MESSAGING_SENDER_ID`** → champ `messagingSenderId`
6. **`VITE_FIREBASE_APP_ID`** → champ `appId`

### Configuration Firestore requise (dans la console Firebase)

Créer 4 collections avec les règles suivantes :

| Collection | Champs du document |
|---|---|
| `contacts` | `nom`, `email`, `telephone`, `message`, `createdAt`, `status` |
| `demandesVoyages` | `nom`, `email`, `telephone`, `destination`, `dateDepart`, `budget`, `nbPersonnes`, `typeVoyage`, `message`, `createdAt`, `status` |
| `demandesImmobilier` | `nom`, `email`, `telephone`, `typeBien`, `budget`, `localisation`, `message`, `createdAt`, `status` |
| `demandesNettoiement` | `nom`, `email`, `telephone`, `typeService`, `frequence`, `surface`, `lieu`, `message`, `createdAt`, `status` |

### Règles Firestore (en mode test pour le développement)
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{collection}/{document} {
      allow read, write: if true;
    }
  }
}
```
> ⚠️ Pour la production, on verrouillera les règles après les tests.

## Étapes d'implémentation

### 1. Installation Firebase SDK
- `npm install firebase` dans `src/frontend/`
- Alternative : `npm install @firebase/firestore` (module individualisé)

### 2. Créer `src/frontend/src/lib/firebase.ts`
Configuration et initialisation de Firebase :
```typescript
import { initializeApp } from "firebase/app";
import { getFirestore } from "firebase/firestore";

const firebaseConfig = {
  apiKey: import.meta.env.VITE_FIREBASE_API_KEY,
  authDomain: import.meta.env.VITE_FIREBASE_AUTH_DOMAIN,
  projectId: import.meta.env.VITE_FIREBASE_PROJECT_ID,
  storageBucket: import.meta.env.VITE_FIREBASE_STORAGE_BUCKET,
  messagingSenderId: import.meta.env.VITE_FIREBASE_MESSAGING_SENDER_ID,
  appId: import.meta.env.VITE_FIREBASE_APP_ID,
};

const app = initializeApp(firebaseConfig);
export const db = getFirestore(app);
```

### 3. Créer `src/frontend/src/lib/firestoreService.ts`
Service générique pour les opérations Firestore :
```typescript
import { collection, addDoc, getDocs, query, orderBy, serverTimestamp } from "firebase/firestore";
import { db } from "./firebase";

export async function submitForm(collectionName: string, data: object) {
  return addDoc(collection(db, collectionName), {
    ...data,
    createdAt: serverTimestamp(),
    status: "pending",
  });
}

export async function getSubmissions(collectionName: string) {
  const q = query(collection(db, collectionName), orderBy("createdAt", "desc"));
  return getDocs(q);
}
```

### 4. Remplacer les appels Appwrite dans les formulaires

Modifier le handler `handleSubmit` de chaque page :

| Page | Ancien (Appwrite) | Nouveau (Firebase) |
|---|---|---|
| `Contact.tsx` | `databases.createDocument(...)` | `submitForm("contacts", data)` |
| `Voyages.tsx` | `databases.createDocument(...)` | `submitForm("demandesVoyages", data)` |
| `Immobilier.tsx` | `databases.createDocument(...)` | `submitForm("demandesImmobilier", data)` |
| `Nettoiement.tsx` | `databases.createDocument(...)` | `submitForm("demandesNettoiement", data)` |

### 5. Supprimer le code Appwrite
- Supprimer `src/frontend/src/lib/appwrite.ts`
- Supprimer ou commenter `src/frontend/src/hooks/useBackend.ts`
- Retirer `VITE_APPWRITE_*` des variables d'environnement
- Désinstaller `@appwrite/sdk` si plus utilisé

### 6. Fichiers à modifier

| Action | Fichier |
|---|---|
| **Créer** | `src/frontend/src/lib/firebase.ts` |
| **Créer** | `src/frontend/src/lib/firestoreService.ts` |
| **Modifier** | `src/frontend/src/pages/Contact.tsx` |
| **Modifier** | `src/frontend/src/pages/Voyages.tsx` |
| **Modifier** | `src/frontend/src/pages/Immobilier.tsx` |
| **Modifier** | `src/frontend/src/pages/Nettoiement.tsx` |
| **Modifier** | `src/frontend/.env` |
| **Modifier** | `src/frontend/.env.example` |
| **Supprimer** | `src/frontend/src/lib/appwrite.ts` |
| **Supprimer** | `src/frontend/src/hooks/useBackend.ts` (si non utilisé ailleurs) |

### 7. Rebuild et redeploy
- `pnpm build`
- Déployer sur Netlify

## Points d'attention
- Firestore a des limites gratuites généreuses (50,000 lectures/mois, 20,000 écritures/mois) — suffisant pour le trafic actuel
- Les règles Firestore sont en mode test pour le moment — à verrouiller avant mise en production
- EmailJS reste fonctionnel (ne dépend pas de Appwrite)
